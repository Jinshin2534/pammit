# パミット モバイルアプリ実装仕様書

更新日: 2026-10-04

本書は、操作マニュアル、Figma、`pammit` の実装済みAPI、`pammit-notes` PR #5、およびUI実装前の仕様確認で決定した内容をひとつにまとめたものである。

## 1. 仕様の優先順位

資料間で内容が衝突した場合は、次の順に判断する。

1. 本書で「確定」とした内容
2. `pammit` の現行実装と本番API仕様
3. 提出済み操作マニュアルのp.2〜p.9
4. Figmaの共有ページ「UIよろしくお願いしま＝＝＝＝す🏃‍♀️」と「材料置き場」
5. `pammit-notes` PR #5の `docs/ui-components.md`
6. `pammit-notes` の現地調査資料とUX上の根拠

本書で変更した用語、Bottom Sheet、担当者表示などは、Figmaと `pammit-notes` にも同期する。日付入りの活動計画は本仕様の根拠として使わない。

## 2. 対象・前提

- 対象端末はAndroidスマートフォン。Pixel 7aでの表示・動作確認を行う。
- 対象者は師匠農家、後継者、アルバイト。最優先の利用者は作業に不慣れな後継者・アルバイト。
- 本番APIは `https://13-192-68-51.sslip.io/api/v1` を使用する。Swagger UIは `/docs`。
- 農園コードは `kamiyama-01`。
- サーバー通信は通常時に必要。通信断時は、進行中作業の判定・終了・「今日の気づき」だけを端末へ保存する。

### 3.1 コードの境界

- 画面内に `fetch` を書かない。サーバー通信は `src/api/` から呼ぶ。
- 帽子との通信は `src/hat/` から呼ぶ。
- 果実検出、文字起こし、音声合成は野﨑さんの部品を使う。
- 摘む/残すの判断は `src/judge.ts`。
- 未提供のネイティブ部品は、同じ型とエラー形式を持つダミーで代替する。

## 5. ロールと権限

| 操作 | 師匠農家 `owner` | 後継者・アルバイト `worker` |
|---|---|---|
| 一般画面の閲覧 | 可 | 可 |
| 予定の閲覧・作成 | 可 | 可 |
| 予定の変更・削除 | すべての予定 | 自分が作成した予定だけ |
| 予定から作業開始 | 自分が担当、または担当者未指定 | 自分が担当、または担当者未指定 |
| 作業者・園地の管理 | 可 | 不可 |
| 農園日誌・PDF | 可 | 不可 |
| 判定結果の送信 | 自分の作業だけ | 自分の作業だけ |

停止済み作業者は既存・過去の予定に氏名を残す。新規作成と担当者変更の選択肢からは除外する。

## 7. 認証と端末保存

### 7.1 ログイン

1. 役割「師匠農家さん」または「後継者・アルバイト」を選ぶ。
2. 名前を選ぶ。
3. 4桁のPINを入力する。

- 名前一覧はその端末での初回だけ表示する。
- 2回目以降は前回利用者の名前をPIN画面に表示する。
- 「別の人でログイン」で役割・名前選択へ戻る。
- PINは保存しない。認証トークンだけをSecureStoreへ保存する。
- トークンの有効期間は30日。失効時は前回利用者名付きのPIN画面へ戻す。
- PINを5回間違えたら15分ロックする。残り時間と「別の人でログイン」を表示する。

### 7.2 端末に保存する値

- 前回利用者の `user_id`、名前、役割
- 選択中の `plot_id`
- 音量
- 話す速さ
- 未送信判定、未送信の作業終了、未送信の音声メモ
- 日誌備考の未送信下書き

## 8. 画面仕様

### 8.1 ホーム

- 今日のひとこと: 短い文と「詳しく」で開く説明。
- 今日の予定: 農園内の全予定を時間順に表示する。時間、作業、園地、担当を表示する。
- 「作業を始める」「ベテランAI相談」「予定管理」を表示する。
- 通信断時は「通信が切れています」と、利用できない機能を表示する。

### 8.2 作業開始

1. 今日の予定から選ぶか、新しく始める。
2. 園地を選ぶ。
3. 作業を選ぶ。
4. 帽子へ接続し、判定モデルを読み込む。
5. 内容を確認し、開始する。

作業種別は剪定、灌水、肥料、摘果・摘葉、収穫、防除、草刈り、その他の8種類。帽子の判定を行うのは摘果・摘葉と収穫だけ。

- 予定の作業種別が複数の場合、すべてを表示し、開始する1種類を選ぶ。
- 進行中の作業や同期待ちの終了処理がある間は新しい作業を開始できない。
- 帽子用モデルを読み込めない場合、判定が必要な作業は開始させない。「再試行」と「別の作業を選ぶ」を表示する。
- マイク権限は必要になった直前に要求する。

### 8.3 作業中・終了

- 園地名、作業種別、経過時間を表示する。
- 帽子判定の対象作業では「切る / 残す / 判断不可」の件数を表示する。
- 再起動後はサーバーの同期済み件数と端末の未送信件数を合算する。
- 「同期済み○件 / 未送信○件」を小さく表示する。
- 作業中のAI相談は作業セッションへひも付け、AI相談ログで表示する。
- 帽子が切れた場合、「帽子との接続が切れました。帽子の電源と距離を確認してください」と表示する。
- 作業終了は長押し→確認→フィニッシュの順。
- 通信断中の終了は実際の終了時刻を端末へ保存し、「同期待ち」と表示する。

### 8.4 作業セッション復帰

- ログイン後に `GET /work-sessions?active=true` を呼び、ログイン中の `user_id` で絞り込む。
- 未終了セッションがあれば作業中画面へ復帰し、続行または終了を選べる。
- 利用者は同時に1件のみ作業できる。
- 万が一複数件が返った場合は一覧を出し、再開または終了するセッションを選ぶ。

### 8.5 今日の気づき

- 作業終了後の録音は任意。
- 文字起こしに失敗したら「もう一度録音」と「今回はスキップ」を表示する。
- 通信断中は音声、文字、記録時刻を端末へ保存し、未送信中であることを表示する。
- 通信復旧後に自動送信する。

### 8.6 予定

- 月カレンダーで作業種別の色を円グラフ状に表示する。
- 1日に6〜8種類あってもSVGで最大8分割する。実装時間が厳しい場合の初版に限り、5種類+その他の表示を許容する。
- 予定は1日ずつ入力し、開始・終了時刻を必須とする。
- Figmaにあった曜日の入力行は作らない。
- 作業と担当者は複数選択できる。人数のハード上限は設けない。
- 予定カードに担当者を最大5人表示する。6人以上は「ほかN名」を付け、詳細で全員を表示する。
- 同じ予定に複数作業がある場合、同じ時間でも作業種別ごとに緑色のカードを分けて表示する。データ上は1件の予定のままとする。
- カードを押すとBottom Sheetを開き、全作業、全担当者、備考、編集、削除を表示する。
- Bottom Sheetを閉じても月、選択日、スクロール位置を維持する。
- 削除時は確認ダイアログを出し、完了後にカレンダーとホームを更新する。

### 8.7 農園

- 画面上部に園地選択を置く。選択中の `plot_id` は端末で覚える。
- 保存済みIDが `GET /plots` の結果にない、または `404 plot_not_found` の場合は保存値を破棄し、先頭の園地へ切り替える。
- 園地が0件の場合は空状態を表示し、ownerには園地登録への導線を出す。
- 初版で `plots.active` や園地の一時停止は追加しない。
- 土壌水分の現在値、前日差、明日予測、灌水助言、明日の天気を表示する。
- `suggested_schedule` があるときだけ「確認を明日の予定に追加」を表示する。
- データ推移は土壌水分、気温、湿度、気圧のタブ。
- 土壌水分は過去7日+明日予測、気温・湿度・気圧は過去7日を表示する。期間選択は設けない。

#### 欠損値

- `null` は0ではなく、有効な測定値がないことを意味する。数値部分は `--` と表示する。
- 履歴がなければ「測定データがありません」と表示する。
- 土壌水分の校正値がなければ「土壌水分が校正されていません」と表示する。
- グラフの欠損点は0にせず線を途切れさせる。
- 更新失敗時は前回値を残し、「更新できませんでした」と表示する。

### 8.8 ベテランAI相談

- テキストチャット、過去の会話一覧、アプリに固定で持つサジェスト話題を提供する。
- APIが503 `ai_unavailable` を返したら「AI相談は今使えません」と表示する。
- 入力中の文を消さず、再試行できるようにする。
- 作業中の音声相談は最初だけ合図の言葉を使い、回答後も数秒は続けて聞き取る。

### 8.9 設定

- 帽子の接続状態。
- 音量。
- 話す速さ: はやい / ふつう / ゆっくり / すごくゆっくりの4段階。
- 音量と速さは端末へ保存し、入力欄の近くに「保存しました」を表示する。
- プロフィールは名前とアプリ内の固定アイコン。APIにはアイコンIDだけを送る。端末写真のアップロードは行わない。
- ログアウトは確認ダイアログを出す。

### 8.10 管理者画面

ownerだけに表示する。

- 作業者登録: 名前、性別、種別、週の最大稼働時間。登録後にサーバー発行のPINを1回だけ表示する。
- 作業者の登録人数にハード上限を設けない。
- 園地登録: 名前、所在地。
- 農園日誌: 天気、最高・最低気温、作業人数、作業内容は自動。備考だけ手入力。
- 備考は入力停止から1秒後、キーボードを閉じたとき、画面離脱時に保存する。
- APIに送る前に端末へ下書きを保存し、失敗時は再送する。初版は最後に保存された内容を正とする。
- PDFはサーバーが返すURLをブラウザで開く。

## 9. 通信断と同期

### 9.1 オフライン中に許可する操作

| 操作 | 可否 |
|---|---|
| 進行中作業の判定 | 可。端末保存 |
| 進行中作業の終了 | 可。実際の終了時刻を端末保存 |
| 今日の気づき | 可。音声・文字・記録時刻を端末保存 |
| 新規作業開始 | 不可 |
| 予定の作成・変更・削除 | 不可 |
| AI相談 | 不可 |

利用できない操作には「この機能には通信が必要です」と表示する。

### 9.2 判定キュー

- 判定ごとに `client_event_id`, `user_id`, `session_id`, `detected_at`, `trigger_type`, `verdict`, `reason_code`, `confidence`, `target`, `model_version`, `image_key` をSQLiteへ保存する。初版では画像本体を保存・送信しない。
- 最大200件ずつ送る。
- `accepted` と `duplicated` はキューから削除する。
- 通信失敗と503等は待ち時間を増やしながら再送する。
- 認証切れは同じ利用者の再ログイン後に再送する。
- `rejected` は自動再送を止め、失敗記録を残す。
- ログアウトしても未送信データは削除しない。別の利用者のログイン中は送信しない。

### 9.3 終了・音声メモのキュー

- 終了イベントは `ended_at` を保持し、復旧後にその時刻で送信する。
- 終了同期が完了するまで新規作業は開始できない。
- 音声メモは音声ファイル、文字起こし、記録時刻、`client_event_id`, `user_id`, `session_id` を保持する。

## 10. 判定結果のサーバー保存

- `POST /work-sessions/{session_id}/detections` は仮実装から永続化実装へ変更する。
- ユニークな `client_event_id` で重複を除外する。
- 判定は作業セッションを開始した本人だけが送信できる。
- 全判定のメタデータを保存する。初版では画像を保存しない。
- 応答は `accepted`, `duplicated`, `rejected` を返す。
- 作業セッション詳細は `take`, `keep`, `unknown` の同期済み件数を返す。

## 11. 仕様追加が必要なAPI

### 11.1 担当者候補

- 認証必須の `GET /api/v1/assignee-candidates` を追加する。
- ログイン中の農園に属する `active=true` の作業者を全件返す。
- 応答は `id`, `name`, `role`。初版はページ分割を行わず、アプリ側で検索と仮想化を行う。
- owner専用の `GET /users` とは分離する。

### 11.2 作業者状態

- owner向け作業者応答に `active` を追加する。
- 停止済み作業者を新規担当者として指定できないよう、サーバーでも検証する。

### 11.3 予定権限

- 予定応答に `created_by` を追加する。
- PATCH/DELETEは作成者またはownerだけに許可する。
- 閲覧とPOSTは認証済み全利用者に許可する。

### 11.4 判定件数

- `GET /work-sessions/{id}` または同等の詳細応答に、同期済み判定の件数を追加する。
- 端末は未送信キューの件数を加算し、画面の合計とする。

## 12. エラーと通知

### 12.1 ネイティブ部品のエラー

| コード | 意味 |
|---|---|
| `HAT_UNREACHABLE` | スマートフォンから帽子へ接続できない |
| `MODEL_LOAD_FAILED` | モデルが見つからない、破損、または期待バージョンと不一致 |
| `CAPTURE_FAILED` | 帽子カメラの撮影やJPEG取得に失敗 |
| `INFERENCE_FAILED` | 画像の前処理、推論、後処理に失敗 |
| `TRANSCRIPTION_FAILED` | 文字起こしに失敗 |
| `AUDIO_PLAYBACK_FAILED` | 音声出力または帽子への音声送信に失敗 |
| `UNKNOWN_ERROR` | 上記に当てはまらない予期しない失敗 |

`SYNTHESIS_FAILED` は定義しない。

作業中の通知はエラー名ごとに文言を変える。帽子から音声を再生できない場合は、スマートフォン本体の振動→画面表示→本体音声の順で代替通知する。

### 12.2 APIエラー

- 401 / `token_expired`: 前回利用者名付きのPIN画面へ戻す。
- 423 / `pin_locked`: 残り時間と別の利用者への導線を表示する。
- 503 / `ai_unavailable`: 「AI相談は今使えません」。
- `plot_not_found`: 保存中の園地IDを破棄し、一覧を再取得する。
- 通信失敗: オフライン中の機能制限と同期状態をBannerで表示する。

## 14. 実装とテストの範囲

### 14.1 実装順

1. 本書とFigmaの用語・画面差分を同期する。
2. 判定保存、担当者候補、`active`、判定件数、予定権限をバックエンドに実装する。
3. バックエンドのマイグレーションとテストを追加する。
4. `mobile/` を構築し、テーマと共通部品を実装する。
5. 認証、予定、作業、農園、AI相談、設定、管理画面を実装する。
6. ネイティブ部品のダミーを本実装へ差し替える。
7. Pixel 7aの実機で表示、文字拡大、システムバー、通信断、再起動復帰を確認する。

### 14.2 必須のテスト

- PINの5回失敗、15分ロック、30日トークン、前回利用者への復帰。
- 予定の作成者とownerのPATCH/DELETE、第三者の拒否。
- 停止済み作業者の候補除外と、既存予定での表示維持。
- 判定の保存、同じ `client_event_id` の重複除外、他人のセッションへの送信拒否。
- 最大200件のバッチ、部分成功、`accepted/duplicated/rejected` の整合。
- 通信断中の判定、終了、音声メモが再起動後も残り、同じ利用者だけが再送できること。
- 同期待ち中の新規作業開始拒否。
- 複数の進行中セッションが返った場合の選択。
- センサーの `null`、校正値なし、履歴なし、更新失敗の表示。
- AI相談の503、モデル読み込み失敗、帽子切断、音声再生失敗時の代替通知。
- Bottom Sheetの開閉後にカレンダー位置を維持すること。
- 日誌備考のデバウンス、離脱時保存、未送信下書き復帰。
