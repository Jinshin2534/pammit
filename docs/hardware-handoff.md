# ハード開発の引き継ぎ

ハードウェアの具体設計・部品選定・試作はハード開発担当に委ねます。
以下は既存要件の整理と、実装前にアプリ担当と合わせる項目です。未確定の数値を確定仕様として扱わないでください。

## 担当範囲と構成

| 対象 | 既存要件 | 担当の境界 |
|---|---|---|
| 帽子 | Raspberry Pi Zero 2 W、カメラV3、マイク、スピーカー | 撮影・音声入出力を担当 |
| スマートフォン | Android / React Native、Wi-Fiテザリング | 推論・判定・定型音声・クラウド連携を担当 |
| 常設センサーユニット | BME280・土壌水分センサー | 帽子とは別に園地へ設置。計測値を送信 |

帽子→スマホは映像をMJPEG、音声をPCMで送信し、スマホ→帽子のPCMを再生します。
一次応答はトリガーから1秒以内が要件です。インターネットがなくても、帽子とスマホ間のローカルWi-Fiで判定・定型音声が完結する構成にします。

## 着手順（提案）

1. 帽子とAndroid端末をテザリングで接続し、MJPEG映像を受信する。
2. マイクのPCM送信と、スマートフォンから返したPCMのスピーカー再生を確認する。
3. アプリ担当と統合し、トリガーから音声再生までの遅延を測定する。
4. インターネット切断時の一次応答と、Wi-Fi切断後の再接続を確認する。
5. 常設センサーは別系統として、スタブAPIへの送信から確認する。

## アプリ担当と実装前に合わせること

- MJPEGのURL・ポート、解像度、フレームレート、接続検出方法。
- PCMのサンプリング周波数、ビット深度、チャンネル数、転送方式、バッファ方針。
- 接続開始・停止・再接続の手順、音声の回り込みへの対策。
- 電源、連続稼働時間、装着重量、配線固定、発熱や雨への試作上の対策。
- 実装に必要な部品表・配線図・起動手順・測定結果の共有方法。

これらの詳細値は現行資料では確定していません。部品購入や実装前に担当間で決め、リポジトリへ記録してください。

## 常設センサーの接続

[API仕様](requirements/04-api.md) のF-10を参照してください。

- Wi-Fi直結: `POST /api/v1/ingest/sensor`、認証ヘッダーは `X-Device-Key`。
- 送信データ: `measured_at`、`temperature`、`humidity`、`pressure`、`soil_moisture_raw`、`battery_pct`。
- 土壌水分はADC生値を送り、換算はサーバー側。送信間隔の目安は10〜30分。
- LoRaWANはTTN Webhookの受け口を設計済みですが、通信方式の採用は未確定です。
- LoRaWANの10バイト形式はAPI資料を参照。バイトオーダーや欠測値の扱いは接続前に合意が必要です。

バックエンドの起動手順は [こちら](../backend/README.md)。Swagger UIはローカルの `http://localhost:8000/docs` で確認できます。現状はスタブのため、送信成功だけで保存や認証の実装完了とは判断できません。

## 優先度と保留事項

帽子の映像・音声連携を優先します。既存要件でF-10センサーは優先度「中」であり、本選デモでは手入力による代替が可能です。

園地マップと土壌水分による灌水判断支援は、[保留中の機能候補](README.md) です。本選スコープには含めず、設置位置・閾値・通知需要のヒアリング後に採否を決めます。

[構成イメージのMermaidソース](diagrams/pammit-system.mmd) は将来案を含みます。LoRaWANや園地マップの採用確定を示すものではありません。
