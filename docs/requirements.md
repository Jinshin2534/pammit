# 要件

画面の構成は操作マニュアル（Figma）に合わせる。

## 利用者

| ロール | ログイン画面の表示 | できること |
|---|---|---|
| `owner` | 師匠農家さん | すべての画面と管理者画面 |
| `worker` | 後継者さん / アルバイト | 管理者画面以外 |

一番に考える利用者は、作業に慣れていない後継者とアルバイト。

| 操作 | `owner` | `worker` |
|---|---|---|
| 予定を見る・作る | できる | できる |
| 予定を変える・消す | すべての予定 | 自分が作った予定だけ |
| 予定から作業を始める | 自分が担当、または担当者のない予定 | 同じ |
| 作業者・農地の管理、農園日誌 | できる | できない |
| 作業を終える・判定結果を送る・今日の気づきを残す | 自分の作業だけ | 自分の作業だけ |

停止した作業者は、新しい予定の担当者には選べない。すでにある予定には名前を残す。

## 用語

| 言葉 | 意味 | DB |
|---|---|---|
| 農園 | 経営体。ログインとデータの分離の単位 | `farms` |
| 農地 | 実際に作業する場所（三番ハウスなど）。1つの農園に複数ある | `plots` |

画面では農地も「農園」と表示する（「農園を選ぶ」「農園登録」など）。

## 画面と機能

### ログイン

- 役割を選び、名前を選び、4桁の PIN を入力する
- 端末は前回ログインした人を覚えておき、PIN 画面に名前を出す。初めての端末では名前の一覧から選ぶ。「別の人でログイン」で役割の選択に戻れる
- PIN は管理者が作業者を登録したときにサーバーが発行し、登録完了時に一度だけ表示する
- PIN を5回間違えると15分ロックする。ロック中は残り時間と「別の人でログイン」を出す
- ログインの有効期間は30日。切れたら、前回の人の名前を出した PIN 画面に戻る
- 端末には PIN を残さず、ログインのトークンだけを安全な領域に保存する

### ホーム

- 今日のひとこと（短い文と、詳しく見たときの説明文）
- 今日の予定（農園のすべての予定を時間順に。時間・作業・農地・担当）
- 「作業を始める」「ベテランAI相談」「予定管理」への入口

今日のひとことは、予定・センサーの値・天気予報をもとに LLM が毎朝5時に生成する。OpenAI のキーがないときや失敗したときは、同じ材料から決まった形の文を作る。

### 作業を始める

1. 今日の予定から選ぶか、新しく始める
2. 農地を選ぶ
3. 作業を選ぶ
4. 帽子に接続する（カメラ・マイク・スピーカーの確認、音声のテスト）。帽子を使わずに始めることもできる
5. 内容を確認して開始する

作業はログインしている人のものになり、作業者を選ぶ手順はない。

作業の種類は次の8つ。

| 作業 | 帽子での判定 |
|---|---|
| 剪定 | なし |
| 灌水 | なし |
| 肥料 | なし |
| 摘果・摘葉 | あり |
| 収穫 | あり |
| 防除 | なし |
| 草刈り | なし |
| その他 | なし |

すべての作業を「作業セッション」として記録する。作業ログはセッションの終了時に自動で作る。

- 予定に作業が複数あるときは、すべて出して、始める1つを選ぶ
- 予定の農地と作業はそのまま使う。始められるのは、自分が担当の予定か、担当者のない予定
- 担当者が複数いる予定は、それぞれが自分のスマートフォンで同じ予定から作業を始める
- 1人が同時に進められる作業は1つ。終わっていない作業や、送り終わっていない終了があるあいだは、新しい作業を始めない。サーバーも断る
- 摘果・摘葉と収穫も、帽子なしで始められる。そのときは判定せず、作業の時間だけを記録する
- 帽子を使うときに判定のモデルや判定の設定を読み込めなければ、帽子を使って始めない。「再試行」と「別の作業を選ぶ」を出す
- マイクの許可は、使う直前に求める

### 作業中・終了

- 農地・作業・経過時間を表示する。帽子を使って判定する作業では、切る / 残す / 判断不可の件数も表示する
- 件数はサーバーに送った分と端末に残っている分を足したもの。内訳（送信済み○件 / 未送信○件）を小さく出す
- 作業中に AI 相談ができ、その会話は作業セッションに紐づけて残す
- 帽子との接続が切れたら「帽子との接続が切れました。帽子の電源と距離を確認してください」と出す
- 帽子から音声を出せないときは、スマートフォンの振動、画面の表示、スマートフォンからの音声の順に代わりに知らせる
- 作業終了は長押しで行い、確認画面を出す
- 終了後に「今日の気づき」を音声で残せる（任意）。スマートフォンで文字に起こし、音声と文字の両方をサーバーに送る。文字に起こせなかったら「もう一度録音」と「今回はスキップ」を出す

ログインしたとき、終わっていない自分の作業があれば作業中の画面に戻り、続けるか終えるかを選べる。

### 作業中の音声での相談

作業中は、帽子に話しかけて AI 相談ができる。画面の AI 相談と同じ会話として保存し、作業画面の「AI相談ログ」に出す。

```text
帽子のマイク → スマートフォン: 文字に起こす → サーバー: AI 相談 → スマートフォン: 音声合成 → 帽子のスピーカー
```

- 文字起こしはスマートフォンで行う。日本語専用の音声認識モデル ReazonSpeech（sherpa-onnx）を使い、声を外部に送らない
- 音声合成は Android 標準の機能で音声ファイルを作り、帽子に送って再生する
- 最初だけ合図の言葉を言う。答えのあと数秒は続けて聞き取り、黙れば会話を終える
- 音声で答えるときは、2〜3文（100字くらいまで）で、箇条書きや記号を使わない。アプリは質問に `mode: "voice"` を付けて送る

### 判定

作業者が帽子に向かって合図すると、スマートフォンが帽子から画像を1枚取得し、果実を検出して判定する。
結果は帽子のスピーカーから定型の音声で伝える。

| 判定 | 意味 |
|---|---|
| `take` | 摘む / 切る |
| `keep` | 残す |
| `unknown` | 判断できない |

自信がないときは `unknown` を返す。初心者向けの道具が自信を持って間違えることを最も避ける。
判定結果はその場でサーバーに送る。送る項目は [ai.md](ai.md) の検討結果に合わせて決める。画像は送らない。

### 予定

- 月のカレンダーに、その日の作業の種類を色分けした円で表示する。最大8つに分ける
- 日を選んで予定を入力する（時間・農地・作業・担当・備考）。開始と終了の時刻は必ず入れる。作業と担当は複数選べ、人数に上限はない
- 予定は人が入力する。1日ずつ登録し、くり返しの登録はしない
- 予定のカードには担当を5人まで出し、6人以上は「ほかN名」とする
- 1つの予定に作業が複数あるときは、作業ごとにカードを分けて出す（データは1件のまま）
- カードを押すと下から詳細が開き、すべての作業・担当・備考と、編集・削除を出す。閉じても月・選んだ日・スクロールの位置はそのまま
- 削除の前に確認を出す。消したらカレンダーとホームを更新する

### 農園

- 画面の上で農地を切り替える。選んだ農地は端末が覚えておく。覚えていた農地がなくなっていたら、一覧の先頭に切り替える
- 農地が1つもないときは空の状態を出し、`owner` には農地の登録への入口を出す
- 土壌水分の現在値、前日との差、明日の予測を表示する
- 灌水についての助言を表示し、「確認を明日の予定に追加」で予定を1件作れる
- データ推移の画面で、土壌水分・気温・湿度・気圧のグラフを表示する。過去7日分で、土壌水分だけ明日の予測も足す
- 明日の最高気温と雨量を表示する

値がないときは0にしない。

| 状態 | 表示 |
|---|---|
| 値がない | 数字の部分を `--` |
| 履歴がない | 測定データがありません |
| 土壌水分の校正値がない | 土壌水分が校正されていません |
| グラフの途中が欠けている | 線を途切れさせる |
| 更新に失敗した | 前の値を残し、「更新できませんでした」 |

土壌水分（%）は、センサーの生値から農地ごとの2点校正（乾燥時・飽和時）で換算する。
明日の予測は、直近の変化を直線で延ばして求める。
灌水の助言はルールで出す。上から順に判定し、最初に当てはまったものを表示する。

| 条件 | 表示 |
|---|---|
| 明日の雨が10mm以上で、今の値が目安以上 | 明日は雨の予報です。今すぐの灌水は必要なさそうです |
| 今の値が目安（既定28%）未満 | 土が乾き気味です。今日中に土の状態を確認しましょう |
| 明日の予測が目安未満 | 明日には目安を下回りそうです。明日午前に土の状態を確認しましょう |
| 6〜9月で、24時間で減っていて、明日の最高気温が33℃以上 | 晴天が1週間続く場合は灌水を検討しましょう |
| どれにも当てはまらない | 今すぐの灌水は必要なさそうです |

言い方は「確認を促す」形に限り、灌水量は断定しない。目安・雨量・気温の値は農地ごとに変えられる。
すだち専用の数値基準は公的資料に見当たらないため、これらの値は県の指針（晴天が1週間続いたら灌水）をもとにした仮の値である。
明日すでに灌水の予定がある農地では「確認を明日の予定に追加」を出さない。
天気予報は Open-Meteo の気象庁モデルから1日1回取り込む（気象庁の予報 JSON には雨量がないため）。農地に緯度経度がなければ神山町の位置を使う。

### ベテランAI相談

- テキストで相談する。よく聞かれる話題をサジェストとして表示する
- 過去の会話を一覧で見られる
- 質問に応じて、AI が知識（現地調査・聞き取り・「今日の気づき」）、農地の状態、予定、作業の記録を調べて答える
- 回答に出典は出さない
- AI を使えないときは「AI相談は今使えません」と出す。入力した文は消さず、もう一度送れるようにする

### 設定

- 帽子の接続状態の確認
- 音量、話す速さ（はやい / ふつう / ゆっくり / すごくゆっくり）。端末に保存し、入力欄の近くに「保存しました」と出す
- プロフィール（名前と、アプリに入っているアイコンから1つ）。端末の写真は使わない
- ログアウト（確認を出す）

### 管理者画面（owner のみ）

- 作業者の登録・削除（名前・性別・作業者の種別・週の最大稼働時間）。人数に上限はない。削除は停止として扱う
- 農地の登録・削除（名前・所在地）。削除した農地は一覧と新しい予定・作業に出さず、過去の予定・作業ログ・日誌には名前を残す
- 農園日誌: 経営体で1日1件。備考だけ手で書き、ほかは記録から自動で作る
    - 気温: その日の全センサーの最高・最低。センサーがない日は空欄
    - 天気: その日の朝に取り込んだ天気予報
    - 作業人数・作業内容: その日の作業ログから数える（予定は入れない）
- 備考は、入力が1秒止まったとき・キーボードを閉じたとき・画面を離れたときに保存する。先に端末に残し、送れなかったら送り直す。複数の端末で書いたときは、最後に保存したものを残す
- 日誌の PDF: 期間を指定し、1日1行の表と作業の明細（時間・作業者・農地・作業）を出す。サーバーで作り、アプリは10分間だけ開ける URL をブラウザで開く
- 日誌は作業日誌で、JA に出す生産履歴（農薬の記録）の代わりにはならない。農薬の名前・倍率・量の記録と提出用の様式は、JA の様式を手に入れてから考える

## 通信が切れたとき

ふだんはサーバーとの通信を前提にする。通信が切れているあいだにできるのは、進めている作業の判定・終了と「今日の気づき」だけで、端末に残して通信が戻ったら送る。

| 操作 | 通信が切れているとき |
|---|---|
| 進めている作業の判定 | できる。端末に残す |
| 進めている作業の終了 | できる。実際に終えた時刻を残し、「同期待ち」と出す |
| 今日の気づき | できる。音声・文字・記録した時刻を残す |
| 新しい作業を始める | できない |
| 予定を作る・変える・消す | できない |
| AI 相談 | できない |

できない操作では「この機能には通信が必要です」と出す。

- 端末に残したものは、再起動しても消えない
- 判定は200件ずつまとめて送る。登録済み・重複は端末から消し、通信の失敗やサーバーの一時的なエラーは間をあけながら送り直す。サーバーが受け付けなかったものは送り直さず、記録を残す
- ログインが切れたら、同じ人がログインし直してから送る。ログアウトしても消さず、別の人がログインしているあいだは送らない

## 非機能要件

| 項目 | 要件 |
|---|---|
| 応答時間 | 合図から最初の音声まで1秒以内 |
| 通信 | スマートフォンと帽子はテザリングの Wi-Fi で接続する。サーバーとの通信はインターネット接続を前提にする |
| 二重登録 | 書き込みは端末が作る `client_event_id` で重複を判定し、同じ要求が2回届いても1件にする |
| データの分離 | 農園（経営体）ごとにデータを分け、ログイン中の人の農園のデータだけを返す |
| 端末の負荷 | 判定は合図があったときだけ行い、常時の推論はしない |
| 対象端末 | Android のスマートフォン。Pixel 7a で確かめる |

## 決まっていないこと

- 判定結果としてサーバーに送る項目の形
- 会話を続けて聞き取る秒数と、作業中の音声での答えの長さ
- 音量・話す速さを帽子側で変えられるか
